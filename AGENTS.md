# Работа над FlyEl-TRX

## GitHub и несколько компьютеров

Пользователь разрешил обычный цикл получения и публикации изменений для этого проекта.

1. Перед изменениями прочитайте этот файл и выполните `git status --short`, затем `git fetch --prune origin`.
2. Если рабочая копия чистая, обновите текущую ветку через `git pull --ff-only`. На основной ветке используйте `main` и `origin/main`.
3. Если есть локальные правки, сначала изучите их и сохраните. Не применяйте автоматический `reset --hard`, `clean` или `stash`. Обновляйте ветку только без потери чужих изменений; неоднозначный конфликт обсудите с пользователем.
4. После завершения задачи выполните проверки, `git diff --check`, добавьте только относящиеся к задаче файлы, создайте осмысленный коммит и отправьте его в GitHub. Повторное подтверждение обычного commit/push не требуется.
5. Если push отклонён из-за новых коммитов, получите изменения и согласуйте историю без force-push. Если нужен защищённый процесс через PR — используйте ветку и PR. Сообщайте о блокирующих ошибках доступа.
6. В конце укажите результат проверок, коммит и факт успешной отправки. Не заявляйте, что код проверен на плате, если это не выполнялось.

## Архитектура и стиль

- Проект Keil находится в корне: `gmg12864_v01.uvprojx`. Не перемещайте его без необходимости: пользователь открывает этот файл в IDE.
- Состав и зависимости модулей описаны в `firmware/ARCHITECTURE.md`.
- Изменения RF, TS и состояния принадлежат `radio_control.c`; отображение — модулям `ui_*` и `lcd_*`.
- Не помещайте операции I2C, LCD, задержки и форматирование в обработчики прерываний. EXTI4 только будит клавиатуру; TIM2 обслуживает ввод и базу 500 мкс.
- Ориентир для C-файла — 150–400 строк. При росте примерно выше 500 строк выделяйте самостоятельную ответственность, а не случайный диапазон строк.
- К публичным функциям и нетривиальным алгоритмам добавляйте короткие русские комментарии: назначение, единицы измерения, контекст вызова и ограничения. Не пересказывайте каждую очевидную операцию.
- Исходники и документация — UTF-8. Не заменяйте растр шрифта автоматическим масштабированием без запроса пользователя.
- Аппаратные назначения сверяйте с `src/board_pins.h`, `firmware/PINOUT.md` и исходной таблицей в `doc/`.
- Сохраняйте поведение, подтверждённое на плате. Отдельно указывайте, если рефакторинг требует повторной аппаратной проверки.

## Проверка и сборка

- `powershell -ExecutionPolicy Bypass -File scripts/test.ps1` — проверки логики TS, CRC и адресации EEPROM без платы.
- `powershell -ExecutionPolicy Bypass -File scripts/build.ps1` — полная сборка и линковка ARM, предупреждения считаются ошибками.
- После изменений клавиатуры/каналов выполняйте также `scripts/test-arm.ps1`: Thumb-код исполняется в Unicorn; установка зависимости — `tests/requirements.txt`, инструкция — `firmware/KEYBOARD.md`.
- Пути инструментов можно передать через `-ToolchainBin` и `-PacksRoot`; подробности в `firmware/README.md`.
- При добавлении C-файлов обновляйте также список в `.uvprojx`. Скрипт сборки обнаруживает `src/*.c` автоматически.
- Не отправляйте `Objects`, `Listings`, `RTE`, конфигурацию окон IDE, скачанные инструменты, старые архивы и секреты. Они исключены через `.gitignore`.
