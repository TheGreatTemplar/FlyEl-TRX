# Прошивка FlyEl-TRX

Текущая прошивка для **STM32F103C8T6**, кварц 8 МГц, SYSCLK 72 МГц.
Проект Keil оставлен в корне: [`gmg12864_v01.uvprojx`](../gmg12864_v01.uvprojx).

## Первый запуск на другом компьютере

1. Установите Git и Keil MDK с **Arm Compiler 6.16**. Проверенная IDE — µVision 5.36.
2. В Pack Installer установите **ARM::CMSIS 5.8.0** и **Keil::STM32F1xx_DFP 2.4.1**.
3. Клонируйте проект:

   ```powershell
   git clone https://github.com/TheGreatTemplar/FlyEl-TRX.git
   cd FlyEl-TRX
   ```

4. Откройте `gmg12864_v01.uvprojx`, выберите `GMG12864`, выполните Rebuild.
5. Загрузите `Objects/gmg12864_v01.hex` через привычный программатор/SWD.

CMSIS подключён как компонент пакета, startup берётся из установленного DFP.
Абсолютных путей к профилю автора в проекте нет. Настройки окон и отладчика создаются отдельно на каждом компьютере.
Исходники — **UTF-8**; эту кодировку следует выбрать в редакторе при необходимости.

## Сборка без IDE

Из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/test.ps1
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
```

Скрипты находят пакеты через `CMSIS_PACK_ROOT` или `%LOCALAPPDATA%/Arm/Packs`.
Компилятор ищется в PATH и стандартных каталогах Keil. Нестандартные пути передаются явно:

```powershell
./scripts/build.ps1 -ToolchainBin 'D:/Keil/ARM/ARMCLANG/Bin' -PacksRoot 'D:/Arm/Packs'
./scripts/test.ps1 -ToolchainBin 'D:/Keil/ARM/ARMCLANG/Bin' -PacksRoot 'D:/Arm/Packs'
```

Можно также задать `FLYEL_TOOLCHAIN_BIN` и `CMSIS_PACK_ROOT` в окружении своего компьютера.
Компилятор и SDK не входят в репозиторий.

Результат: `build/FlyEl.hex`, `build/FlyEl.axf`, `build/FlyEl.map`.
Компилируются все `src/*.c`; `-Wall -Wextra -Wsign-conversion -Wpadded` считаются ошибками.
Оба способа используют 64 КБ Flash и 20 КБ SRAM.

## Работа с двух компьютеров

Перед началом проверьте местные правки и получите обновления:

```powershell
git status --short
git pull --ff-only
```

После изменений выполните проверки, просмотрите состав коммита и отправьте результат:

```powershell
./scripts/test.ps1
./scripts/build.ps1
git diff --check
git status --short
git add -A
git diff --cached --stat
git commit -m "Describe the firmware change"
git push
```

Перед переходом на другой компьютер завершайте этот цикл. Если рабочая копия грязная или pull сообщает о расхождении истории, сначала сохраните и согласуйте изменения. Не используйте force-push и жёсткий сброс для устранения конфликта.
Порядок работы помощника закреплён в [`AGENTS.md`](../AGENTS.md).

## Что работает сейчас

- CLK0 Si5351 — 500 кГц, CLK1 — RF + выбранная ПЧ; при перестройке CLK1 временно отключается.
- Девять КВ-диапазонов; после включения — 10 м, 28,200 МГц, шаг 100 Гц.
- Энкодер — четыре перехода на щелчок для текущего макета.
- CD4017: 27 кнопок; EXTI4 будит сканер, после отпускания он снова засыпает.
- **TS = Key_10_3**: короткое нажатие 10 → 100 → 1000 → 10 Гц; удержание строго больше секунды — 10 кГц; следующее нажатие возвращает сохранённый шаг.
- AT24C256C на PB8/PB9: чтение всех 32 КБ, CRC-16/CCITT-FALSE, процент и время чтения на стартовом экране. Для полностью заполненной `FF` памяти CRC равен `FF00`.
- Экран 128×64, SW2019 17/15, второй VFO 7×11/5×7, заставка три секунды.
- [Назначены функции клавиатуры](KEYBOARD.md): VFO A/B, MODE, FUNC, память, SCN, SET и состояния внешних блоков.
- ATT: OFF, −6…−42 дБ с шагом 6; маска ступеней 6/12/24 дБ готова для будущего драйвера реле.
- 99 каналов в AT24C256C: запись удержанием MW, две копии с CRC и проверкой чтением.

CRC — сумма прочитанных данных, без сравнения с сохранённым эталоном и без теста записи.

### Стартовые проверки

Порядок: текстовый протокол → заставка **3 секунды** → рабочий экран.
Шрифт протокола 5×7, между строками два пустых ряда пикселей (шаг 9).
Во время чтения EEPROM справа вращается `| / - \\`, обновление примерно раз в 100 мс.
Показанное время EEPROM включает чтение, расчёт CRC, разбор записей и обновления дисплея.
Искусственных пауз между блоками нет; после успешного результата протокол остаётся на 600 мс.

- `SI5351 I2C OK` — успешная инициализация/обмен, без утверждения об исправности RF-выхода.
- `EEPROM OK`, время и `CRC:XXXX` — все 256 блоков по 128 байт прочитаны.
  При ошибке одного блока чтение остальных продолжается; частичная CRC не выдаётся за полную.
- `USED` / `FREE` / `BAD` — занятые, свободные и недоступные каналы из 99.
  Учитывается новейшая исправная копия, включая запись об очистке и переполнение поколения.
  Полностью `FF` — незаписанная копия. Одна повреждённая копия при исправной второй
  не делает канал `BAD`, но остаётся в журнале. Непрочитанные каналы не считаются свободными.
- Копии настроек UART также проверяются по формату и CRC; затем восстанавливается UART
  (`UART EEPROM OK`) либо остаются настройки по умолчанию (`UART DEFAULT`).

При любых диагностических замечаниях загрузка ожидает в журнале. Вращение энкодера
листает по одной строке с ограничением на концах, **F-INP** продолжает к заставке.
Строки указывают адрес блока (`READ FAIL @4080`), канал и копию (`CH 02 B: CRC ERROR`),
ошибку формата (`FORMAT ERR`) или отсутствие исправных копий (`NO VALID COPY`).
CRC неподписанных областей EEPROM не сравнивается с эталоном; там выявляются ошибки чтения.
Журнал хранит состояния, а строки строит по запросу: число сообщений не обрезается
фиксированным массивом текстов. Диагностика не записывает и не исправляет EEPROM.

Если одна копия исправна, замечание к другой показывается обычным текстом
`CRC WARN` / `FORMAT WARN`; канал остаётся рабочим. `CRC ERROR` и инверсная
`NO VALID COPY` означают отсутствие исправной копии. Первый успешный MW создаёт
одну копию; вторая, заполненная FF, не считается ошибкой. Наличие CRC WARN само
по себе не означает повреждения активной записи и не требует стирания памяти.

Спиннер проходит кадры последовательно при каждом обновлении экрана: пропуск
интервала из-за обмена I2C не возвращает его на тот же угол. У второй программной
I2C (PB8/PB9) паузы привязаны к DWT CYCCNT: 72 такта при SYSCLK 72 МГц = 1 мкс,
три паузы на бит. Это ускоряет прежний цикл из 80 итераций и сохраняет частоту
SCL ниже 400 кГц; точная частота зависит от инструкций GPIO, подтяжек и ёмкости шины
и должна измеряться на плате. Первая I2C для Si5351 не менялась.

### Начальная инициализация EEPROM

Вход: держать **SET + FILTER 5 секунд**, выбрать **17 SERVICE DATA → 17.03 EEPROM INIT**.
Открывается подтверждение с **NO** по умолчанию. Энкодером выбрать **YES**, затем
нажать **F-INP** или **DN**. До начала операции **UP / NR/.** отменяют её.

Операция стирает **все 32 КБ EEPROM в FF**, включая 99 каналов, обе копии UART
и любые другие данные в микросхеме. Это инициализация пустого хранилища, а не
восстановление потерянных каналов. Во время операции питание не выключать.
Каждая из 512 страниц по 64 байта записывается, ожидается ACK и проверяется чтением.
Процент отражает только уже проверенные страницы; при сбое видны причина и число
проверенных байтов. Остальные операции с EEPROM блокируются до перезапуска.

После `FACTORY RESET OK` нажать **F-INP**, чтобы перезапустить прибор. После ошибки
та же кнопка перезапускает прибор с частично стёртой памятью; успешно завершённый
сброс не объявляется. Возврат к рабочему экрану без перезапуска запрещён, чтобы не
использовать старый кэш. После успешной инициализации и перезапуска: 99 свободных
каналов, UART **115200 8N1**, CRC пустой EEPROM **FF00**.

Разбор выполняется при полном проходе; существующие автоматы затем отдельно загружают
рабочий кэш каналов и UART, повторного полного чтения 32 КБ нет.

Тесты `tests/boot_arm.c` проверяют пустую память, резервирование, очистку, ошибки блоков,
отсутствующее устройство и прокрутку сотен ошибок; `tests/display_arm.c` — геометрию,
наличие нужных символов и два пустых ряда между строками. Проверки выполняются без платы.

VFO B теперь хранит самостоятельную настройку; после старта оба VFO имеют 28,200 МГц, LSB.
Внешние блоки ещё не подключены: их кнопки меняют программные состояния и индикацию.
Ширины FILTER и передающие измерители ещё не заданы; NR/ANF отложены по раскладке. S-метр линейный по напряжению.
SET открывает Quick Set; инженерное меню доступно из пункта ENG. Подробный порядок — в [описании кнопок](KEYBOARD.md).

## Проверки

`scripts/test.ps1` компилирует тестовые сценарии вместе с настоящими C-функциями TS и EEPROM.
В оптимизированном LLVM IR утверждения должны свестись к успешному возврату; оставшиеся вызовы и условные ветвления считаются ошибкой.
Проверяются цикл шагов, граница секунды, возврат из 10 кГц, переполнение таймера, вектор CRC, потоковый CRC, адреса 0x50–0x57, ошибки шины и границы чтения.
Это проверки логики без MCU; они не проверяют электрические уровни и временные параметры макета.
После изменений клавиатуры, таймингов, синтезатора или шрифтов нужна отдельная проверка на плате.

`scripts/test-arm.ps1` дополнительно исполняет реальный Thumb-код Cortex-M3 в Unicorn:
проверяет целые жесты кнопок, ввод частоты/канала, ATT, VFO, MODE, меню, сканирование,
запись/очистку каналов, WP и восстановление после повреждённой записи.
Установка тестовой зависимости и команды приведены в [KEYBOARD.md](KEYBOARD.md#проверки-без-платы).

## Форматирование C-кода

Стиль Allman, четыре пробела, один оператор на строку и две пустые строки после
каждого определения функции закреплены в `.clang-format` и `AGENTS.md`.
Проверка без изменения файлов (путь к clang-format зависит от установки Keil):

```powershell
python scripts/format_code.py --formatter 'C:/Keil_v5_ARM/ARM/ARMCLANG/Bin/clang-format.exe' --check
```

Для применения уберите `--check`. Скрипт проверяет сохранность токенов C перед
записью, форматирует `src/` и `tests/`, оставляет растры шрифтов и заставки
без изменений. Межфункциональные интервалы устанавливает скрипт, поскольку
обычного clang-format для требования ровно двух пустых строк недостаточно.
